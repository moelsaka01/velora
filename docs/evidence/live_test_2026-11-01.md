# Live test, 2026-11-01

Release build (`build/Release/velora-shell.exe`, `velora-watchdog.exe`, built from main dfb6607 sources), real Explorer, Windows 11 10.0.26200, **1 monitor** (`\.\DISPLAY1`, 1280x720), non-elevated. Explorer was never killed by Claude; keys were pressed by the user. Probe: `tools/live_probe.ps1` (read-only). Logs: `%LOCALAPPDATA%\Velora\logs`.

Baseline: taskbar visible, auto-hide off, work area y=0 h=672, no `%LOCALAPPDATA%\Velora` state, Explorer PID 9624.

| Step | Result | Evidence |
|---|---|---|
| a. Enter | PASS | Taskbar hidden (user confirmed visually and probe: `primary=hidden`); auto-hide fallback on; work area y=28 h=692 (28 px appbar). Log: `enter: done` 16:11:07. |

Log: `TaskbarCreated: ... re-hiding taskbars and re-registering appbars` at 16:20:38 and again 16:20:53 (two messages for one restart). |
| c. Ctrl+Alt+Shift+Esc (user, physical) | PASS | Watchdog log: `restore done in 391 ms (taskbars visible after 328 ms)`. Taskbar visible, auto-hide off, work area y=0 h=672 (equal to baseline), marker and state.json gone, no Velora processes. |
| d. TerminateProcess of velora-shell only | PASS | Taskbar visible 180 ms after the kill (budget 1 s); watchdog `restore done in 219 ms`; baseline state restored; no Velora processes left. |
| e. Enter, then normal exit (`velora-shell --exit`) | PASS | Exit returned 0 in 254 ms; baseline restored; only `logs` left in the Velora dir (no marker, state.json consumed). |
| f. `velora-watchdog --restore` at the end | PASS | Exit 0; state unchanged from baseline (taskbar visible, auto-hide off, work area y=0 h=672). |

## Observations and limitations
- Only one monitor was available: the secondary taskbar (`Shell_SecondaryTrayWnd`) hide/restore and per-monitor work areas are **unmeasured** live. "Every monitor" in step a is only verified for the single monitor.
- Cosmetic: while in Velora Mode the menu bar appbar is a blank white 28 px strip (appbar window has no background brush; menu bar not drawn yet, menubar G1 not started). Not a failure of the switch gate.
- Step b: `TaskbarCreated` was handled twice for one restart; the end state was correct. Cause not investigated.
- In step c the watchdog terminated the (live) shell before restoring, as designed (`terminating velora-shell ... before restore`).
- Dock appbar is not implemented yet, so the work area reflects the menu bar appbar only.
